# Hermes Workflow — Конвенции хранения данных

## Память никогда не перегружать

**Правило:** Никогда не перегружай `memory` (лимит 2200 chars). Для больших объёмов данных всегда используй отдельные файлы.

**Почему:** Memory загружается в КАЖДУЮ сессию. Если забит — невозможно добавить новые факты без удаления старых.

**Как делать:**

| Что нужно сохранить | Куда писать |
|---------------------|-------------|
| Короткий факт о среде/пользователе | `memory` (до 2200 chars) |
| Разбор проекта, реверс-инженеринг | `/root/kb/projects/<имя>.md` |
| Процедура/рецепт для повторного использования | Скилл (`skill_manage`) |
| Ссылка на внешний ресурс | Релевантная KB-заметка или reference скилла, не глобальная memory |
| Результаты исследования | Файл + применимые правила в существующем скилле |

## Где что хранить

- `/root/kb/` — база знаний, разборы проектов
- `/root/kb/projects/` — детальные разборы
- Скиллы — процедуры и workflow, загружаются по триггеру
- `/root/.secrets/` — только секреты (и пути к ним, не значения)

## Пример

**Задача:** Сохранить полный разбор Dewiar (93 модуля, ~64 КБ).

**Неправильно:** Записать всё в `memory` — переполнение, потеря старых фактов.

**Правильно:**
1. Записать полный разбор в `/root/kb/projects/dewiar-reverse-engineering.md`
2. В скилле `dewiar-reverse-engineering` — применимые правила и ссылка на полный файл.
3. Глобальную `memory` не менять ради каждого исследования; туда подходят только устойчивые факты, нужные независимо от текущей задачи.
