# Mailbox operations (read + send from a real account)

Give the agent working access to the user's own mailbox: list, search, read, reply,
send, attach, file. Two transports, chosen by what the host actually allows — not by
what the provider documents.

## When to Use

- «Можешь пользоваться моей почтой?», «отправь письмо от моего имени».
- A bot or campaign needs to send from a real address, not a no-reply.
- Inbox triage / digests over a mailbox the user owns.

## Always-on rules

1. **Probe the ports before designing anything.** Outbound 25/465/587 are blocked on
   most VPS hosts (anti-spam policy) while 443 and 993 stay open. Check with
   `/dev/tcp` and `openssl s_client`; if SMTP is dead, sending goes through the
   provider's HTTP API and reading stays on IMAP. Never promise mail sending before
   that check.
2. **The password never enters a config file or a knowledge base.** Keep it in a
   `600` file and let the client read it at runtime (`password.command = ["cat",
   <path>]`). The address goes in its own file, the config is generated by a script.
3. **Verify read and send separately.** Read: folder list → search → open one message.
   Send: message to the account's own address → confirm it appears in Sent. A send
   returning `200` proves the provider accepted it, not that a human can read it.
4. **Run the user's own approval gate on outbound mail.** Any message to a third party
   is shown to the user first, word for word; his mailbox is his identity.
5. **A personal mailbox is not a platform.** ~20 messages a day before the provider
   throttles; bulk sending belongs on a verified domain through a sending service.
6. **Localised folder names are normal.** Gmail in a Russian UI has
   `[Gmail]/Отправленные`, `Черновики`, `Корзина`, `Спам`, `Вся почта`. Map them as
   aliases once, then use `-m sent` / `-m trash` everywhere.

## Procedure

1. **Collect credentials.** Address + provider app password (Gmail: 2FA, then
   https://myaccount.google.com/apppasswords). The user drops both into the secrets
   dir with `600`; the agent never reads a password out of chat.
2. **Generate the config** from a script (template:
   `templates/himalaya-gmail.toml`), then `mailbox list` to learn the real folder
   names, then fix the aliases. Details: `references/himalaya-v2-cli.md`.
3. **Read/search** through the CLI: `envelope list`, `envelope search`, `message read`,
   `attachment download`, `flag add/remove`, `message move`.
4. **Send.** If SMTP answers, `message send` with a MIME body on stdin. If not,
   switch to the provider API: `references/gmail-api-send.md` (OAuth consent → refresh
   token → `messages/send`, `In-Reply-To` + `threadId` for replies).
5. **Prove it end-to-end:** send yourself one message, then read Sent through IMAP and
   show the row. Report both transports in one line each.
6. **Write it down** in the project KB (endpoint, paths, alias map, what is proven and
   what is only configured) — the next session starts from there.

## Pitfalls

- **`himalaya` v2 is not v1.** `folder.aliases` is gone (`mailbox.alias` now),
  `template send` is gone (`message send`), search is its own subcommand with
  space-separated conditions (`from kwork`, `not flag seen`) — `from:kwork` fails.
- **Options go before the query.** `envelope search --page-size 5 "not flag seen"`
  parses; putting `--page-size` after the query swallows it into the query text.
- **OAuth consent is not enough: the project must have the API enabled.** Otherwise
  every call returns `403 Gmail API has not been used in project … or it is disabled`
  with the enable URL in the message — send that URL to the user, the refresh token
  stays valid.
- **The redirect URI must already be registered on the OAuth client.** Reuse an
  existing one (a local callback page that answers 401 still leaves `?code=…` in the
  address bar) rather than inventing `localhost:1`. The code is single-use and dies in
  minutes; a pasted redirect URL is not a password.
- **Test the client before the flow:** posting a bogus refresh token to the token
  endpoint distinguishes `invalid_grant` (client valid) from `invalid_client` (wrong
  secret) in one request.
- **No IPv6 detour.** A host without a global IPv6 address cannot reach
  `smtp.gmail.com` over its AAAA record — do not spend time on it.

## Verification

- `mailbox list` returns real folders; `envelope search "from <known sender>"` returns
  rows; `message read <id>` shows headers and body.
- A message sent to the account's own address appears in Sent over IMAP.
- A reply keeps the thread (same `threadId`), which the IMAP side shows as `Re: …` in
  the same conversation.
